# gRPC contracts

All contracts live in one buf module: `packages/contracts/proto/`. One module means
one lint config, one breaking-change check against `main`, and one set of generated
TypeScript that every service and the gateway import from `@ga/contracts/ga/<domain>/v1/<file>`.

## Layout and naming (buf STANDARD enforces most of it)

- File: `proto/ga/<domain>/v1/<domain>.proto`, package `ga.<domain>.v1` (lower_snake).
- Service `<Domain>Service`; RPCs are verbs + resource: `CreateHouse`, `GetHouse`,
  `ListHouses`, `UpdateHouse`, `DeleteHouse`, custom actions like `CancelBooking`.
- Every RPC has its own `<Rpc>Request` and `<Rpc>Response` message, even when small.
  Wrapper responses (`GetUserResponse { User user = 1; }`) can grow without breaking callers.
- Fields `lower_snake_case`; TypeScript sees them as camelCase.
- Enums: `BOOKING_STATUS_UNSPECIFIED = 0;` first, every value prefixed with the enum name.
- Shared types go in `ga/common/v1/` (today: `ga.common.v1.Money`). Add one only when two
  services genuinely share the concept.
- Document every RPC with the gRPC status codes it returns; reviewers and the gateway rely on it:

  ```proto
  // CreateBooking reserves a house for a date range.
  // Errors: INVALID_ARGUMENT, FAILED_PRECONDITION (guest or house missing),
  // ALREADY_EXISTS (dates overlap), UNAVAILABLE (a dependency is unreachable).
  rpc CreateBooking(CreateBookingRequest) returns (CreateBookingResponse);
  ```

## Platform API conventions (a pragmatic AIP subset)

| Concern        | Convention                                                                                                                                                          |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Ids            | `string id = 1;` UUIDv7 generated by the server                                                                                                                     |
| Timestamps     | `google.protobuf.Timestamp create_time / update_time` (+ e.g. `cancel_time`)                                                                                        |
| Calendar dates | `string` `YYYY-MM-DD`, documented as inclusive/exclusive                                                                                                            |
| Money          | `ga.common.v1.Money { currency_code, amount_minor }`                                                                                                                |
| List           | `int32 page_size = 1; string page_token = 2;` + optional filters; response `repeated X xs = 1; string next_page_token = 2;` (empty = last page)                     |
| Partial update | `UpdateXRequest { string id = 1; optional string title = 2; Address address = 3; ... }`: proto3 `optional` scalars, message fields replace the whole value when set |
| Delete         | `DeleteXResponse {}`                                                                                                                                                |
| Errors         | gRPC status + `google.rpc.ErrorInfo` (reason, domain, metadata) + `google.rpc.BadRequest` for validation, produced by the service kit                               |

We use proto3 `optional` instead of `FieldMask` for updates: it is type-safe in
TypeScript and needs no path mapping. `optional` scalars keep presence, so a caller can
set `description: ''` or `max_guests: 0` explicitly and the server sees it. What cannot be
expressed is clearing a **message** field (an unset `Address` arrives as `null`, which
means "unchanged"); add an explicit field or RPC when you need that.

## Workflow

```bash
# edit proto/ga/<domain>/v1/<domain>.proto
pnpm --filter @ga/contracts codegen      # buf lint + generate + postgen + descriptors
pnpm --filter @ga/contracts breaking     # compare with main (needs main in .git)
pnpm --filter @ga/contracts test
pnpm typecheck                           # every consumer re-checks (turbo "transit" tasks hash dependencies)
```

Generated files (`src/gen/**`) and `descriptors.binpb` are committed: reviewers see the
TypeScript impact, and nobody needs buf to build. Never edit them by hand.

## Evolving a contract without breaking callers

Safe: add a field with a new number, add an RPC, add an enum value (old readers see the
raw number; keep a `default` branch), add an optional filter.

Breaking (blocked by `buf breaking` with FILE rules, run in CI on every PR): rename or
renumber a field, change a type, remove anything, rename a package/service/RPC, reuse a
number. Renames break TypeScript callers even when the wire is unchanged, which is why the
check uses FILE, not WIRE. Under FILE, deleting a field fails even when you `reserved` its
number and name.

To change something breaking: add the new field/RPC, migrate callers, mark the old one
`[deprecated = true]` and leave it in place. Removing it later is a deliberate, reviewed
exception (a PR that touches `buf.yaml` breaking `ignore_only` for that file, with
`reserved 4; reserved "old_name";` in the proto). A truly new API is `v2`
(`ga.<domain>.v2`) served side by side with `v1` until callers move.

## Runtime behaviour you must know (generated types vs. what arrives)

Services use `@grpc/proto-loader` at runtime with fixed options (see
`packages/contracts/src/runtime/loader.ts`), matched by the ts-proto options in
`buf.gen.yaml`. Consequences:
- Unset **message** fields arrive as `null` (typed `?: T | null`). Unset `optional`
  scalars are absent. Unset plain scalars arrive as `''`, `0`, `false`.
- Enums are strings (`'BOOKING_STATUS_CONFIRMED'`); unset = the `_UNSPECIFIED` value. An
  unknown enum string from a client becomes the 0 value silently, so validate enums.
- `int64` is a JS `number`: values above 2^53 lose precision. Use it for counters and
  money minor units only; ids are strings.
- `Timestamp` is a JS `Date` only because `installWellKnownTypes()` (called by the kit's
  bootstrap, the gateway and the test client) teaches protobufjs. Without it a `Date` is
  silently sent as 1970-01-01. Any new entrypoint that makes gRPC calls must call it.

More detail and the reasons behind the post-generation step: `references/codegen.md`.

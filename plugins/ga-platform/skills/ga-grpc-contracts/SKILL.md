# gRPC contracts

All contracts live in one buf module: `packages/contracts/proto/`. One module means
one lint config, one breaking-change check against `main`, and one set of generated
TypeScript that every service and the gateway import from `@ga/contracts/ga/<domain>/v1/<file>`.

## Layout and naming (buf STANDARD enforces most of it)

- File: `proto/ga/<domain>/v1/<domain>.proto`, package `ga.<domain>.v1` (lower_snake).
- Service `<Domain>Service`; RPCs are verbs + resource: `CreateHouse`, `GetHouse`,
  `ListHouses`, `UpdateHouse`, `DeleteHouse`, custom actions like `CancelBooking`.
- Every RPC has its own `<Rpc>Request` and `<Rpc>Response` message, even when small.
  Wrapper responses (`GetUserResponse { User user = 1; }`) can grow without breaking callers.
- Fields `lower_snake_case`; TypeScript sees them as camelCase.
- Enums: `BOOKING_STATUS_UNSPECIFIED = 0;` first, every value prefixed with the enum name.
- Shared types go in `ga/common/v1/` (today: `ga.common.v1.Money`). Add one only when two
  services genuinely share the concept.
- Document every RPC with who may call it and the gRPC status codes it returns; reviewers,
  callers and the gateway rely on it:

  ```proto
  // CreateBooking reserves a house for a date range; the calling user is the guest.
  // Access: user.
  // Errors: INVALID_ARGUMENT, FAILED_PRECONDITION (guest account or house missing,
  // too many guests), ALREADY_EXISTS (dates overlap an active booking),
  // UNAVAILABLE (a dependency is unreachable), UNAUTHENTICATED, PERMISSION_DENIED.
  rpc CreateBooking(CreateBookingRequest) returns (CreateBookingResponse);
  ```

- The `Access:` line states the controller's `@Access` policy: `user`, `admin`,
  `identity`, `service (<callers>)` or `public (<reason>)`, plus forwarders
  (`Access: user, also forwarded by house-service and booking-service.`) and rules the
  service adds (`Access: user (owner or admin).`).
- Every RPC lists `UNAUTHENTICATED` (no valid caller assertion, or no principal where a
  user is required). List `PERMISSION_DENIED` where a role, an owner check or a caller
  allowlist can refuse, with the reason when it is a business one
  (`PERMISSION_DENIED (HOUSE_PERMISSION_DENIED)`), and write `NOT_FOUND (also for
  bookings the caller may not see)` where visibility hides resources.

## Platform API conventions (a pragmatic AIP subset)

| Concern        | Convention                                                                                                                                                                                                                                                    |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Ids            | `string id = 1;` UUIDv7 generated by the server                                                                                                                                                                                                               |
| Acting user    | never a request field: the service takes it from the principal (`currentUser()`). Request ids address resources (`house_id`) or filter lists of public data (`owner_id` in `ListHouses`)                                                                      |
| Access         | one `// Access:` line per RPC, matching the controller's `@Access`                                                                                                                                                                                            |
| Timestamps     | `google.protobuf.Timestamp create_time / update_time` (+ e.g. `cancel_time`)                                                                                                                                                                                  |
| Calendar dates | `string` `YYYY-MM-DD`, documented as inclusive/exclusive                                                                                                                                                                                                      |
| Money          | `ga.common.v1.Money { currency_code, amount_minor }`                                                                                                                                                                                                          |
| List           | `int32 page_size = 1; string page_token = 2;` + optional filters; response `repeated X xs = 1; string next_page_token = 2;` (empty = last page). Lists of private data return the caller's own rows (`BookingParty` picks guest or host; `ANY` is admin-only) |
| Partial update | `UpdateXRequest { string id = 1; optional string title = 2; Address address = 3; ... }`: proto3 `optional` scalars, message fields replace the whole value when set                                                                                           |
| Delete         | `DeleteXResponse {}`                                                                                                                                                                                                                                          |
| Errors         | gRPC status + `google.rpc.ErrorInfo` (reason, domain, metadata) + `google.rpc.BadRequest` for validation, produced by the service kit                                                                                                                         |

We use proto3 `optional` instead of `FieldMask` for updates: it is type-safe in
TypeScript and needs no path mapping. `optional` scalars keep presence, so a caller can
set `description: ''` or `max_guests: 0` explicitly and the server sees it. What cannot be
expressed is clearing a **message** field (an unset `Address` arrives as `null`, which
means "unchanged"); add an explicit field or RPC when you need that.

## Workflow

```bash
# edit proto/ga/<domain>/v1/<domain>.proto
pnpm --filter @ga/contracts codegen      # buf lint + generate + postgen + descriptors
pnpm --filter @ga/contracts breaking     # compare with main (needs main in .git)
pnpm --filter @ga/contracts test
pnpm typecheck                           # every consumer re-checks (turbo "transit" tasks hash dependencies)
```

Generated files (`src/gen/**`) and `descriptors.binpb` are committed: reviewers see the
TypeScript impact, and nobody needs buf to build. Never edit them by hand.

## Evolving a contract without breaking callers

Safe: add a field with a new number, add an RPC, add an enum value (old readers see the
raw number; keep a `default` branch), add an optional filter.

Breaking (blocked by `buf breaking` with FILE rules, run in CI on every PR): rename or
renumber a field, change a type, remove anything, rename a package/service/RPC, reuse a
number. Renames break TypeScript callers even when the wire is unchanged, which is why the
check uses FILE, not WIRE. Under FILE, deleting a field fails even when you `reserved` its
number and name.

To change something breaking: add the new field/RPC, migrate callers, then **deprecate**
the old one and leave it in place:

```proto
message CreateHouseRequest {
  // Deprecated and ignored: the owner is the calling user (ADR-0004). To be reserved.
  string owner_id = 1 [deprecated = true];
  ...
}
```

The server drops it from its Zod request schema, so it is ignored. ts-proto marks it
`@deprecated` but keeps a plain (non-`optional`) field required, so TypeScript callers
send the zero value with `// oxlint-disable-next-line typescript/no-deprecated -- the
generated type requires it until the field is reserved` (`no-deprecated` is a warning).
A deprecated RPC gets `option deprecated = true;` (`CreateUser`). **Reserving** it later is
a deliberate, reviewed exception (a PR that touches `buf.yaml` breaking `ignore_only` for
that file, with `reserved 4; reserved "old_name";` in the proto). A truly new API is `v2`
(`ga.<domain>.v2`) served side by side with `v1` until callers move.

## Runtime behaviour you must know (generated types vs. what arrives)

Services use `@grpc/proto-loader` at runtime with fixed options (see
`packages/contracts/src/runtime/loader.ts`), matched by the ts-proto options in
`buf.gen.yaml`. Consequences:
- Unset **message** fields arrive as `null` (typed `?: T | null`). Unset `optional`
  scalars are absent. Unset plain scalars arrive as `''`, `0`, `false`.
- Enums are strings (`'BOOKING_STATUS_CONFIRMED'`); unset = the `_UNSPECIFIED` value. An
  unknown enum string from a client becomes the 0 value silently, so validate enums.
- `int64` is a JS `number`: values above 2^53 lose precision. Use it for counters and
  money minor units only; ids are strings.
- `Timestamp` is a JS `Date` only because `installWellKnownTypes()` (called by the kit's
  bootstrap, the gateway and the test client) teaches protobufjs. Without it a `Date` is
  silently sent as 1970-01-01. Any new entrypoint that makes gRPC calls must call it.

## Event payloads (ADR-0005)

An event's payload is a protobuf message in the **producer's** package, in its own file:
`proto/ga/<domain>/v<N>/<domain>_events.proto` (`ga/house/v1/house_events.proto`). The
message is named `<Aggregate><PastFact>Event` (`HouseDeletedEvent`, `UserDeletedEvent`);
its full name (`ga.house.v1.HouseDeletedEvent`) is also the topic. The kit's
`defineEvent` refuses any other name, and derives the file from it.

```proto
// HouseDeletedEvent: a house was deleted. Aggregate id: the house id.
// Subscribers: booking-service (cancels the house's open stays).
message HouseDeletedEvent {
  // Id of the deleted house.
  string house_id = 1;
  // Id of its owner (ga.user.v1.User) when it was deleted.
  string owner_id = 2;
}
```

- **Envelope versus payload.** The event id, occur time, aggregate id, request id and
  traceparent travel in the bus envelope (`ga.event_bus.v1.Event`); the producer is the
  verified caller of `Publish`. The payload holds domain facts and ids only: never
  personal data (no email in `UserDeletedEvent`) and never a principal.
- Document the aggregate id and the subscribers on the message.
- **Changes are additive only** (same rules as RPC messages above). An incompatible change
  is a new `ga.<domain>.v2.XEvent`, published alongside `v1` until every subscriber has
  moved; then `v1` is retired.
- Payload bytes are encoded with `messageCodec(protoFile, fullName)` from
  `@ga/contracts/runtime`: the protobufjs copy and the conversions RPCs use (camelCase
  keys, scalar defaults, unset messages as `null`, `Timestamp` as `Date` with the
  well-known-type wrappers installed), so a payload looks exactly like an RPC message.
  Codecs are untyped (`decode` returns `Readonly<Record<string, unknown>>`): check-access
  refuses generic casts in production code, so the typed view comes from
  `defineEvent<HouseDeletedEvent>` and the generated interface. Services never call the
  codec themselves; `Outbox.add` and `@OnEvent` do.

More detail, the reasons behind the post-generation step and how to call a running
service by hand (TLS, tokens): `references/codegen.md`.
